显卡驱动程序接口

显卡驱动接口是操作系统或应用程序与显卡硬件之间的软件层，它允许软件（如应用程序、游戏或 WebGPU 这样的图形 API）与显卡进行通信，而无需直接处理硬件的复杂性。

AI 总结

显卡驱动接口就是：

🎯 翻译官：将高级 API 调用转换为硬件指令

🛡️ 安全卫士：防止应用程序直接操作硬件

📊 资源经理：管理 GPU 内存和计算资源

🔄 抽象层：让代码能在不同显卡上运行

devicePixelRatio

当前环境屏幕放大倍数

  • 1.0 普通屏幕 一个 css 像素 = 1 个物理像素点显示
  • 2.0 高清屏幕 一个 css 像素 = （2*2）4 个物理像素点显示（精雕细琢）
  • 3.0 超清屏幕 一个 css 像素 = （3*3）9 个物理像素点显示 （超级精雕细琢）

为什么 webgpu 初始化要调节 ratio

页面上（用户看到的），canvas 仍然是 800*600 css 像素大小

但是 webgpu 实际上是在一个 1600 * 1200 的画布上进行渲染的，比 css 大了 4 倍的像素点

浏览器会自动把 1600x1200 的渲染内容缩小到 800*600 的显示区域

alphaMode

在操作用作图像源的纹理时，会产生影响

  • ‘opaque’ 忽略 alpha 值，如果纹理是透明的，当它用作图像源或显示到屏幕上时，将清除 alpha 通道为 1.0。这是默认值
  • ‘premultiplied’颜色值会与它们的 alpha 值预乘。例如，在 50% alpha 下的 100% 红色是 [0.5, 0, 0, 0.5]

业务上一般用的是预乘，所以读取源纹理拿到纹理颜色后，如何想得到真正的颜色需要 / alpha 明天看看

context.getCurrentTexture()

从已经配置好的渲染上下文中获取 canvas 在当前帧对应的显存（纹理）

注意：为了实现流畅的动画，浏览器会准备多个纹理进行轮换，所以 getCurrentTexture()返回的纹理对象可能是不一样的，所以不能缓存这个纹理供后续使用

标准使用模式是在每一帧的渲染循环中，都调用这个方法来获取当前帧纹理，然后再作为颜色附件使用
